# ELC-RAG / EvoLink 当前进度、实验缺口与下一步计划

日期：2026-09-14  
依据：历史任务中已确认的研究主线、2026-09-11 Gold500 实验结果、项目内论文与实验缺口分析。

## 1. 结论先行：目前做到什么程度

目前已经从“系统原型和小样本可行性验证”推进到“单数据集上的受控检索主线基本成立”。已经能够比较清楚地证明：

1. 三通路结果经过 EvoLink 共享跨视图连接后，能补回更多分散证据；
2. 一次性 Evidence-Need Planning 与 EvoLink 结合后，能进一步提高多证据完整召回；
3. 这两项提升主要发生在 Evidence Recall 和 Complete Recall，而不是前排排序；
4. OnePlan 对 Comparison 问题最有效，但对 Inference 和 Temporal 的排序或局部召回存在退化；
5. 当前还不能证明 EventEffect / 生命周期作用边本身是增益来源，也不能证明检索提升已经稳定转化为更好的最终答案。

因此，项目所处阶段可以概括为：

> **方法已经实现，Gold500 检索主效应已经出现，论文主线已经收敛；但机制归因、端到端收益、跨数据集泛化和统计严谨性尚未闭环。**

若按论文准备度做非精确判断：工程与方法实现已较完整，受控检索实验约完成四分之三；但按强论文证据要求，整体大约处于“完成一半”的位置。

## 2. 当前应冻结的研究主线

历史讨论已经把主线收敛为三个递进方法，而不是继续堆叠多个 EvoNeed 变体：

```text
Ours
  ↓ 增加 EvoLink
Ours + EvoLink
  ↓ 将固定通路查询改为一次性证据需求规划
OnePlan-Shared
```

三者的准确含义如下。

| 方法 | 查询方式 | 检索与扩展 | 研究作用 |
|---|---|---|---|
| Ours | 普通 QueryPlanner；Vector 使用原问题，Graph/Event 使用原问题及结构化提示 | 固定 Vector、Graph、Event 三路，直接融合 | 三视图基础方法 |
| Ours+EvoLink | 与 Ours 相同 | 三路候选合并后做一次共享跨视图扩展 | 验证跨视图连接能否补证 |
| OnePlan-Shared | 一次生成 1—3 个 Evidence Need；每个 Need 有自己的 query、route、knowledge type 和 missing slots | 各 Need 首轮检索后，共享做一次 EvoLink，再进行 Need-level 融合 | 验证面向证据需求的查询是否优于固定通路查询 |

`OnePlan-NoLink` 不是主叙事中的第四个创新，而是 2×2 归因对照：它用于区分 OnePlan 自身的收益与 EvoLink 的收益。

需要继续坚持的表述边界：

- OnePlan 是 **one-shot evidence-need planning**，不是多轮 Agentic gap filling；
- 一个 Need 首轮只选择一个 route，但不同 Need 可以重复选择相同 route；
- OnePlan 的创新不能写成“把三路检索换成三个 Need”；其区别在于按回答所需证据拆分，而非按检索器类型固定拆分；
- EventEffect 是当前 EvoLink 的表示和连接基础，尚未被证明是独立有效的创新模块。

## 3. 9 月 11 日已经取得的核心结果

统一条件：MultiHopRAG Gold500，609 篇文档、2512 个 chunks、500 个非空 Gold 问题，最终输出 Top-20。

| 方法 | Evidence R@20 | Complete R@20 | nDCG@20 | MRR@20 | 平均延迟 |
|---|---:|---:|---:|---:|---:|
| Ours | 0.836 | 0.610 | 0.633 | 0.696 | 4.83s |
| Ours+EvoLink | 0.879 | 0.706 | 0.646 | 0.694 | 1.37s |
| OnePlan-NoLink | 0.841 | 0.640 | 0.623 | 0.649 | 0.71s |
| OnePlan-Shared | **0.900** | **0.766** | 0.637 | 0.645 | 0.92s |
| Hybrid | 0.867 | 0.668 | **0.666** | **0.765** | 0.32s |
| HippoRAG2 | 0.776 | 0.530 | 0.558 | 0.639 | 1.54s |
| EventRAG（项目适配版） | 0.451 | 0.180 | 0.248 | 0.247 | 2.63s |
| E²RAG（项目适配版） | 0.613 | 0.316 | 0.408 | 0.443 | 1.54s |

### 3.1 已经能够支持的结论

1. **EvoLink 的补证作用较明确。** `Ours → Ours+EvoLink` 时，Evidence R@20 提升 4.3 个百分点，Complete R@20 提升 9.6 个百分点；nDCG 小幅提高，MRR 基本不变。
2. **OnePlan 与 EvoLink 结合后进一步提高完整召回。** `Ours+EvoLink → OnePlan-Shared` 时，Complete R@20 从 0.706 提升到 0.766。
3. **最终方法的优势是“找得更全”，不是“第一条排得更准”。** Hybrid 仍然在 nDCG 和 MRR 上领先；因此不能宣称当前最终方法全面优于 Hybrid。
4. **EvoLink 的价值在较深预算处更明显。** Ours 与 Ours+EvoLink 在 Top-5 基本相同，差距主要出现在 Top-20，说明新增证据多位于候选后部。
5. **当前最难的是 Inference。** OnePlan-Shared 的 Inference Complete R@20 高于 Ours，但排序指标下降；与普通 QueryRewrite-Shared 相比，OnePlan 主要提升 Comparison，对 Inference 和 Temporal 有一定损失。

这里的主结论是把 `Ours`、`Ours+EvoLink` 和 `OnePlan-Shared` 与现有图 RAG/事件图 RAG 对照：当前 `Ours` 已在 Evidence/Complete Recall 上高于项目内的 HippoRAG2、EventRAG 适配版和 E²RAG 适配版，说明三视图数据关联方法本身已经形成相对现有图 RAG 的增强。`Hybrid` 是额外增强版本，不纳入“主方法击败现有图 RAG”的结论；它只作为补充上界/速度参照。

### 3.2 参数实验的当前含义

Gold100 参数试跑中，`seed_limit_per_name=5、max_event_seeds=5` 的 `(5,5)` 配置总体最好：OnePlan-Shared 的 Evidence R@20 / Complete R@20 为 0.900 / 0.770。

但这仍是前 100 题上的选择结果，不能直接替代 Gold500 确认实验。当前只能把 `(5,5)` 视为待全量确认的候选参数，不能把它和默认参数 Gold500 结果拼成同一个最终结论。

Gold500 复核入口已经实现：`scripts/run_evolink_param_confirm_2026-09-14.sh`，结果写入 `data/exports/evaluation/2026-09-14_evolink_param_confirm_gold500/`。

## 4. 端到端问答目前做到哪里

### 4.1 已完成

Gold100 pilot 已完成：

| 方法 / 上下文 | EM | Token F1 |
|---|---:|---:|
| OnePlan / Raw | 81.0% | 81.5% |
| OnePlan / Entity-Relation-Event Tables | 82.0% | 82.5% |
| OnePlan / Evolution Structure | 80.0% | 80.5% |
| Hybrid / Raw | 82.0% | 82.5% |
| EvoLink / Raw | 79.0% | 79.5% |

这说明结构化上下文最多只有弱信号；专门的 evolution structure 在 pilot 中反而下降，尚不能作为贡献。

### 4.2 尚未完成

- Gold500 问答批次因 429 限流没有形成有效的完整结果；
- 500 题的 raw/native 上下文已经离线准备好，但“上下文准备完成”不等于“问答评测完成”；
- 目前还没有可靠的 Gold500 EM/F1 主表；
- 还没有 Citation Precision、Citation Recall、supported-claim rate、groundedness 和答案完整性结果；
- 还没有证明 Complete Recall 的提升会稳定带来最终答案提升。

因此，当前论文可以说“检索到更完整的 Gold evidence”，不能说“最终回答显著更准确、更可信”。

### 5.2 当前最关键的七类缺口

#### 缺口一：四方法主表还不是完全预算匹配

Ours/Ours+EvoLink 固定三路各取候选；OnePlan 最多三个 Need，每个 Need 可取 20 个候选，共享 EvoLink 上限还可随 Need 总预算达到 60。虽然最终输出都是 Top-20，但底层候选和扩展预算不完全相同。

已实现固定总候选/固定扩展 cap 的预算匹配入口：固定路由侧为 3 路 × 20 = 60 个首轮候选，OnePlan 侧使用同一个查询级 60 候选总预算（在最多 3 个 Need 间分配），两侧 EvoLink 扩展 cap 都固定为 20；脚本为 `scripts/run_budget_matched_2026-09-14.sh`。

#### 缺口二：还没有证明生命周期作用边有效

当前 `Ours → Ours+EvoLink` 证明的是“跨视图连接整体有效”，不是 EventEffect 的 `CREATES / UPDATES / TERMINATES / SUPERSEDES / DENIES / CONFIRMS` 有效。

已实现首轮机制消融入口，至少需要运行：

```text
Direct Fusion
→ Association-only EvoLink
→ Full EvoLink with EventEffect
```

对应脚本为 `scripts/run_lifecycle_ablation_2026-09-14.sh`；它只关闭 EventEffect 生命周期桥，保留实体/断言/事件关联。

若要更强地讲生命周期，还需 temporal-only、untyped、randomized 和 Gold-transition 上界。

#### 缺口三：OnePlan 的独立价值还不够干净

已实现完全相同共享 EvoLink、候选深度和扩展预算的比较入口：

```text
普通 QueryPlanner / QueryRewrite-Shared
vs.
OnePlan-Shared
```

对应严格配对方法为 `ours_d1_queryrewrite_sharedlink_total` 与 `ours_evoneed_deep_oneplan_shared_total_norerank`，见 `scripts/run_budget_matched_2026-09-14.sh`。

并按 Comparison、Inference、Temporal 报告差异。若 OnePlan 只提升 Comparison、对其他类型持续下降，应考虑题型路由，或把 OnePlan 降为可选增强而非主贡献。

#### 缺口四：最终答案闭环未完成

必须完成 Gold500 raw-context 问答主表，再单独测试结构化上下文。主比较至少包含 Hybrid、Ours、Ours+EvoLink、OnePlan-Shared；统一 reader、prompt、token budget、输出格式和并发策略。

#### 缺口五：只有一个数据集子集

Gold500 适合做大量消融，但不足以证明泛化。最低补法是：

1. MultiHop-RAG 全量非空问题，并单独处理 Null；
2. ChronoQA，直接验证时间、因果和实体状态变化；
3. HotpotQA 或 MuSiQue 二选一，证明不是只对当前新闻语料有效。

#### 缺口六：强基线仍不完整

当前优先补：

1. BM25-only；
2. Hybrid + reranker；
3. KG²RAG；
4. GraphRAG Local；
5. 若保留 OnePlan 主张，再补 LLM decomposition + Hybrid 或 IRCoT 类对照。

外部方法必须区分“受控适配结果”和“原生推荐配置结果”，不能混成一个排名。

#### 缺口七：统计、结构质量与成本证据不足

- 逐题 paired bootstrap 95% CI / 配对显著性尚未完成；
- 缺少新增 Gold、丢失 Gold、噪声证据和扩展路径诊断；
- 缺少 EventEffect、Event—Assertion、Mention—Source 的人工精度；
- DWIE 已显示 Gold Mention 下实体合并较好，但端到端 Mention/Entity 抽取仍弱；
- 延迟受缓存、预热和执行顺序影响，不能把现有秒数直接写成正式效率结论；
- 缺少索引成本、在线 LLM 调用、token、费用和质量—成本 Pareto 曲线。

## 6. 目前最稳妥的论文定位

### 6.1 现在已经能站住的主张

> 面向多源、跨文档的复杂问题，逐片段相关性检索容易返回多条相关内容，却漏掉回答所需的互补证据。EvoLink 从文本、关系和事件检索的局部锚点出发，沿可回到原文来源的跨视图连接进行有界补证，从而提高有限 Top-K 下的证据覆盖与完整召回。

### 6.2 需要实验通过后才能保留的主张

- “EventEffect 生命周期关系带来独立收益”；
- “OnePlan 比普通 QueryRewrite 更适合所有复杂问题”；
- “演化结构提高了答案时间一致性和引用完整性”；
- “最终方法在公平计算预算下全面优于 Hybrid 和现有图 RAG”；
- “系统能够自动判断当前真相或解决来源冲突”。

### 6.3 创新点的建议层级

1. **核心方法：EvoLink 跨视图、来源可追溯的证据补全。** 当前 Gold500 已有较强支持。
2. **查询增强：One-shot Evidence-Need Planning。** 当前有覆盖收益，但需预算匹配、分题型和答案实验后决定是否放主贡献。
3. **生命周期表示：EventEffect。** 目前先作为方法支撑；只有 Full 明显优于 Association-only 后，才升级为核心机制。

## 7. 接下来的执行计划

### 阶段一：冻结并补齐受控检索归因（P0）

1. 冻结 Gold500、609 文档、2512 chunks、query plan、模型版本、代码 commit、随机种子和参数文件，并记录哈希；
2. 用 `(5,5)` 在 Gold500 全量确认 Ours+EvoLink 与 OnePlan-Shared，不能只保留 Gold100 调参结果；
3. 设置统一的首轮候选总预算和 EvoLink expansion cap，跑 20/40/60 预算曲线；
4. 跑 `Direct → Association-only → Full EvoLink`；
5. 完成 `QueryRewrite-Shared → OnePlan-Shared` 的严格配对比较；
6. 生成逐题新增/丢失 Gold、扩展路径、非 Gold 噪声和分题型差异；
7. 对主比较做 paired bootstrap 95% CI 和显著性检验。

阶段一结束后的判定：

- Full 显著优于 Association-only：可以保留“事件作用驱动的演化连接”；
- 两者接近：将创新收缩为“一般跨视图证据协调”；
- OnePlan 在预算匹配后仍提高完整召回且不损伤答案：保留为主方法增强；
- OnePlan 只对 Comparison 有效：改为按题型触发，或放入附录。

### 阶段二：完成 Gold500 端到端闭环（P0）

1. 先只跑 Raw Evidence：Hybrid、Ours、Ours+EvoLink、OnePlan-Shared；
2. 降低并发并断点续跑，避免再次因 429 产生不完整批次；
3. 统一 8k 或 16k token budget，二选一并冻结；
4. 报告 EM、Token F1、答案要点覆盖、Citation Precision/Recall、Groundedness；
5. 只对 Ours+EvoLink 和 OnePlan-Shared 补 `raw+entity_relation`、`raw+evolution`；
6. 结构化上下文若无显著收益，立即从核心贡献中移除。

### 阶段三：补齐论文级外部有效性（P1）

1. MultiHop-RAG 全量非空 + Null 专项；
2. ChronoQA 作为最贴近“演化、时间、因果”的外部验证；
3. HotpotQA 或 MuSiQue 作为普通多跳泛化；
4. 补 BM25-only、Hybrid+reranker、KG²RAG 和 GraphRAG Local；
5. 外部基线分别给出受控赛道和原生赛道结果。

### 阶段四：补结构质量、鲁棒性和效率（P1/P2）

1. 标注 EventEffect / Event—Assertion / Mention—Source 小规模人工集；
2. 做 Gold Entity、Gold Event、Gold EventEffect 上界，定位抽取瓶颈；
3. 测乱序到达、重复报道、来源冲突、时间缺失和噪声边；
4. 独立进程重复测量索引与查询时间，报告 P50/P95、标准差、LLM 调用、token 和费用；
5. 画检索质量—候选预算—上下文 token—延迟/费用曲线。

## 8. 最短可行路线

如果当前目标不是立刻冲击最完整的顶会长文，而是尽快形成一篇逻辑闭合、结果可信的论文，最短路线是：

1. 保留 Gold500 四方法 2×2 主表；
2. 增加严格预算匹配；
3. 增加 Association-only 与 Full EvoLink；
4. 完成 Gold500 统一 Reader 的 Raw 问答；
5. 增加 paired significance 和逐题诊断；
6. 再补一个外部数据集，优先 ChronoQA；
7. 将 OnePlan、结构化上下文和高预算 EvoNeed-Deep 按最终结果决定放主文还是附录。

这条路线完成后，论文主张将从“某个系统在 Gold500 上召回较高”提升为：

> **在统一预算和受控对照下，跨视图连接能够补全分散证据；其机制增益可被消融定位，并能在至少一个外部数据集和统一生成器下带来可验证的下游收益。**
