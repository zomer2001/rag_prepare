# ELC-RAG 下一阶段实验任务

> 日期：2026-09-03
> 新方法名：**ELC-RAG** — **E**vidence **L**inking and **C**oordination for RAG（证据链接与协同 RAG）
> 论文主张：连接原文、Assertion 与 Event 三种视图，返回可连接、可追溯、信息完整的证据；不要求检索器替生成模型裁决最终事实。

## 1. 本轮结论

1. E²RAG、HippoRAG、EventRAG、LightRAG 原本就在本地；此前真正缺的是 KG²RAG 和 Microsoft GraphRAG。
2. KG²RAG 与 GraphRAG 的独立环境现已建好并通过入口验证；**KG²RAG 暂缓，不进入当前实验队列**，GraphRAG 继续准备正式适配。
3. ChronoQA 必须加入。优先使用 E²RAG 的英文叙事版做最近邻对比；中文新闻版作为真实新闻时间问答与中文泛化实验。
4. 论文第一优先级是 **A：证明跨视图连接找到了更多完整证据**。**B：证明记录的时间、状态、来源和 EventEffect 被模型实际利用**较容易实现，但属于第二层贡献。
5. 论文和图表中不再使用含混的 `Ours`。完整方法写作 `ELC-RAG`，关闭跨视图连接写作 `ELC-RAG w/o link`；代码中的 `ours_evolink` 暂时保留，避免此时大规模改名引入回归。

### 2.1 各基线需要什么模型，当前 API 能否替代

当前可直接复用的能力为：

- Chat/抽取 API：`deepseek-v4-flash`，OpenAI-compatible。
- Embedding API：智谱 `embedding-3`，当前配置为 1024 维。
- Reranker：当前没有 Reranker API；配置中的本地 `BAAI/bge-reranker-v2-m3` 未启用，权重也尚未下载。

| 方法 | 官方代码/推荐配置需要的模型 | 当前 API 能否替代 | 下一步建议 |
|---|---|---|---|
| BM25 | 无模型 | 不需要 | 直接运行 |
| Dense | 一个 Embedding 模型 | **可以**：`embedding-3` | 作为所有受控实验的文本向量基线 |
| Hybrid + reranker | Embedding + Cross-Encoder reranker | Embedding **可以**；DeepSeek 不能等价替代 Cross-Encoder | 下载并固定 `BAAI/bge-reranker-v2-m3`；不要临时改成 LLM 打分 |
| LightRAG | 一个抽取/生成 LLM + 一个 Embedding；无强制固定模型 | **可以，当前项目已经这样运行**：DeepSeek + 智谱 | 受控赛道沿用当前 API；记录索引调用数 |
| GraphRAG local | 当前官方默认 `gpt-4.1` + `text-embedding-3-large`；无独立 reranker | **基本可以**：DeepSeek + `embedding-3`，但 DeepSeek 必须先通过 JSON Schema/结构化输出测试 | 受控赛道使用当前 API；原生赛道保留官方 OpenAI 配置 |
| HippoRAG 2 | 官方常用 `gpt-4o-mini` 做 OpenIE/QA，`nvidia/NV-Embed-v2` 做 Embedding；可选事实过滤仍使用 LLM | **可以，现有适配器已用当前 API 跑过 n30** | 受控赛道用 DeepSeek + `embedding-3`；原生赛道用 GPT-4o-mini + NV-Embed-v2 或官方预计算 OpenIE |
| KG²RAG（暂缓） | `llama3:8b`（Ollama）+ `mxbai-embed-large`（Ollama）+ `BAAI/bge-reranker-large` | 生成和 Embedding 可换当前 API，但不能零改动替代 | 保留现有环境即可；当前不下载、不适配、不跑分 |
| EventRAG | 论文实验使用 `gpt-4o` + OpenAI Embedding（代码默认 `text-embedding-3-small`）；无独立 reranker | **可以，现有适配器已用当前 API 跑过低预算版** | 受控赛道用 DeepSeek + `embedding-3`；再补官方预算设置 |
| **E²RAG** | 官方代码默认 `gpt-4o-mini` + `text-embedding-3-small`；HyDE 变体还会用同一 LLM 生成假设文档；无独立 reranker | **可以，而且已经完成适配并跑过 n30**：DeepSeek 负责实体/事件抽取与查询生成，`embedding-3` 负责向量 | ChronoQA 上同时跑“当前 API 受控版”和“官方默认/预计算结果版” |
| `ELC-RAG w/o link` / ELC-RAG | 当前为 DeepSeek 抽取/回答 + `embedding-3`；Reranker 默认关闭 | **已经使用当前 API** | 与外部方法共享同一回答模型；主消融先保持 reranker 关闭 |

结论：GraphRAG 需要先验证结构化输出；其他当前保留的图基线都已经具备或天然支持 OpenAI-compatible API。**技术上能替换不代表可以只报替换结果**：替换 LLM/Embedding 后应标为“受控赛道”；官方模型或官方预计算索引结果单列为“原生赛道”。KG²RAG 只保留为后备基线。

### 2.2 公平使用模型的规则

1. 检索主表统一使用 `embedding-3`，凡更换 Embedding 的方法都重建自己的索引，不能混用旧向量。
2. 端到端回答统一把各方法的最终证据交给同一个 `deepseek-v4-flash` 和同一 Prompt；不让某个基线独占更强回答模型。
3. 图构建/信息抽取属于方法的一部分：受控赛道尽量统一 DeepSeek，原生赛道保留论文推荐模型。
4. Reranker 必须单独记录。Hybrid 与 ELC-RAG 做直接比较时应同时关闭或使用同一个本地 BGE，不能只给其中一个方法增加重排优势。

### 2.3 实际需要下载什么

- **先跑受控赛道：** E²RAG、HippoRAG、EventRAG、LightRAG、ELC-RAG 不需要再下载生成或 Embedding 模型；直接复用现有 DeepSeek 与智谱 API。
- **马上需要：** 只给强文本基线准备 `BAAI/bge-reranker-v2-m3`；当前机器上该权重不存在。
- **暂时不用下载：** `llama3:8b`、`mxbai-embed-large`、`bge-reranker-large`、`nvidia/NV-Embed-v2`。前三项随 KG²RAG 一起暂缓；NV-Embed-v2 只有开始跑 HippoRAG 原生赛道时才需要。
- **GraphRAG：** 不需要本地模型权重；先用极小样本验证 DeepSeek 能稳定返回它要求的结构化 JSON，通过后才能开始全量建图。
- **E²RAG：** 环境和当前 API 适配都已经完成，下一项工作是 ChronoQA 数据适配与正式跑分，不是再配模型。

### 3.1 MultiHop-RAG 全量构成

本地原始文件已重新统计，不使用小样本报告反推：

| 题型 | 题数 | 占比 |
|---|---:|---:|
| Comparison | 856 | 33.5% |
| Inference | 816 | 31.9% |
| Temporal | 583 | 22.8% |
| Null | 301 | 11.8% |
| **合计** | **2,556** | **100%** |

按每题关联的**唯一 gold 文档数**统计：0 篇 301 题、2 篇 1,169 题、3 篇 774 题、4 篇 312 题。609 篇语料文档都至少被某道非 Null 题引用为 gold evidence。这里的 2/3/4 是 gold 文档数，不应未经验证直接写成 2/3/4-hop；同一文档里可能包含多个证据事实。

### 3.2 推荐的正式 n100 抽法

不建议手挑“看起来适合 ELC-RAG”的题，也不建议直接取前 100 题。推荐使用 **题型 × 唯一 gold 文档数双层分层抽样**：

| 层 | 抽取数 |
|---|---:|
| Comparison，2 个 gold 文档 | 27 |
| Comparison，3 个 gold 文档 | 7 |
| Inference，2 个 gold 文档 | 6 |
| Inference，3 个 gold 文档 | 14 |
| Inference，4 个 gold 文档 | 12 |
| Temporal，2 个 gold 文档 | 13 |
| Temporal，3 个 gold 文档 | 9 |
| Null，0 个 gold 文档 | 12 |
| **合计** | **100** |

执行规则：

1. 现有 seed-42 n30 已用于开发和观察，标记为 **dev set**；正式 n100 必须排除这 30 题。
2. 每个层内用固定随机种子 `260903` 抽样，生成并保存 query ID、种子、配额和源文件哈希。
3. 非 Null 题中，同一组 gold 文档最多选 1 题，避免 SBF、Google 诉讼等重复事件占据过多样本；不足时再放宽到 2 题。
4. 抽完后只检查题型、gold 文档数、新闻类别和来源覆盖，不根据任何方法的得分换题。
5. **100 题始终在完整 609 篇文档上检索。** 旧实验的“38 篇 gold + 62 篇干扰文档”只能作为 smoke test，不能作为正式 n100。
6. n100 用于昂贵图基线、消融和端到端生成；论文最终结果仍应尽量把便宜的 BM25/Dense/Hybrid 和 ELC-RAG 核心版本扩到 2,556 题。

上述规则已做只读试抽验证：可以抽满 100 题，与现有 n30 完全不重叠，覆盖 120 篇不同 gold 文档和 27 个新闻来源。当前尚未写出正式 n100 文件，避免在规则确认前提前锁定测试集。

## 4. A：证明跨视图连接有用（最高优先级）

### 4.1 核心对照

保持相同原始文档、切块、Embedding、Top-K/context token、生成模型和评测脚本，只改变跨视图结构：

| 编号 | 方法 | 回答什么问题 |
|---|---|---|
| A0 | Dense | 单纯向量能找到多少证据 |
| A1 | Hybrid + reranker | 强文本检索是否已经足够 |
| A2 | Text + Assertion | 关系视图的独立贡献 |
| A3 | Text + Event | 事件视图的独立贡献 |
| A4 | `ELC-RAG w/o link`：三视图独立检索 + RRF | 多一路结果是否已经足够 |
| A5 | `ELC-RAG entity-link only` | 仅共享实体跨视图是否足够 |
| A6 | `ELC-RAG untyped-effect` | 有连接但不区分 creates/updates/supersedes 等类型 |
| A7 | **ELC-RAG** | 完整跨视图连接与来源回链 |
| N1 | 随机打乱 EventEffect 边 | 排除“任意扩图都能提高召回” |
| N2 | 关闭 Mention→source 回链 | 验证可追溯原文是否是有效组成部分 |

主指标：Evidence Recall@{5,10,20}、Complete Recall@K、nDCG@K、MRR、Precision@K；另外报告“新增证据中 gold/helpful/harmful 的比例”。必须做逐问题 paired bootstrap 95% CI。

重要边界：当前 Effect 类型主要被保存和展示，不一定改变检索排序。因此 A6 与 A7 的检索分数可能相同；类型价值应主要在 B 的答案/引用实验中验证，不能预设它一定提高召回。

### 4.2 与外部基线放在同一张表

当前正式主表顺序：BM25、Dense、Hybrid+reranker、LightRAG、GraphRAG local、HippoRAG 2、EventRAG、E²RAG、`ELC-RAG w/o link`、**ELC-RAG**。KG²RAG 暂缓，后续只在审稿风险需要时补入。

同时给两条赛道：

- **受控赛道**：统一语料、生成模型、上下文 token 和在线调用预算，用于归因。
- **原生赛道**：按各论文推荐配置运行，用于说明复现结果；不能与受控赛道混成一个胜负排名。

## 5. B：证明记录的信息确实被模型使用

### 5.1 难度判断

**代码改动不难，实验也比构造新检索器简单。** 当前普通回答路径已经把 `valid_from/valid_to/status/stance` 写进上下文，EventEffect 类型也已保存在候选 metadata；但 agentic 路径目前只稳定输出 evidence id、document id、channels 和正文，信息传递不一致。

预计工作量：统一 evidence renderer 和消融开关约 1–2 天；跑完整答案、引用、统计和人工复核约 3–5 天，主要成本是模型调用与评测，不是算法开发。

### 5.2 严格实验设计

先冻结同一批检索结果，保证四组看到完全相同的文档和正文，只改变给生成模型的证据表示：

| 编号 | 给模型的内容 |
|---|---|
| B0 | 纯正文 |
| B1 | 正文 + 来源/引用 ID |
| B2 | B1 + 事件时间、事实有效期、状态、来源立场 |
| B3 | B2 + typed EventEffect + 前态—事件—后态连接 |
| B4 | B3，但随机打乱时间/Effect 类型（负对照） |

评价：Answer EM/F1、Citation Precision/Recall、主张支持率、时间/顺序问题准确率、变化原因问题准确率、错误使用过期/冲突证据的比例。若 B3 优于 B2 且 B4 下降，才能说明模型使用了结构记录，而不是只靠正文猜答案。

## 7. 论文最小可发表闭环

只有下面四点同时成立，ELC-RAG 的故事才完整：

1. A4→A7：跨视图连接在相同预算下显著提高完整证据召回，而不是三路简单拼接造成的提升。
2. ELC-RAG 对 GraphRAG、HippoRAG、EventRAG、E²RAG 等最近邻仍有优势或明确互补区间；KG²RAG 当前不作为投稿前置条件。
3. B0→B3：同一证据正文下，结构记录提高回答、引用或时间/因果理解，打乱记录后收益消失。
4. 收益在 MultiHop-RAG 和 ChronoQA 至少两个数据集成立，并报告结构错误与额外成本。

如果第 3 点不成立，不应硬写“EventEffect 帮助生成推理”；仍可把贡献收缩为：**ELC-RAG 通过跨视图连接提高完整、可追溯的证据检索**。
