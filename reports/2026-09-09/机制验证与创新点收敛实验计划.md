# 机制验证与创新点收敛实验计划

日期：2026-09-09

## 一、结论

认可下一阶段方案：现在不应继续零散调参，而应固定方法与评测口径，证明总体收益究竟来自“事件作用驱动的演化连接”还是一般性的“跨视图证据扩展”。最重要的下一组对照是：

> 三路直接融合 → 普通实体—事件关联扩展 → 包含事件—断言作用边的完整 EvoLink

旧版 `2026-09-04_evoneed_planned_q100_r1` 值得复刻，但不能直接作为当前纯检索主结果。它应被命名为高计算量的 `EvoNeed-Deep` 或 `EvoNeed Plan + Assess Rerank`，作为方法上界或原生端到端变体，并与候选深度、LLM 重排都匹配的强对照比较。

## 二、最新指标说明

### 2.1 新一轮 Gold-500

| 方法 | Evidence Recall@20 | Complete Recall@20 | nDCG@20 | MRR@20 |
|---|---:|---:|---:|---:|
| Ours | 0.8362 | 0.6100 | 0.6327 | 0.6964 |
| Ours + EvoLink（权重 0.03） | **0.8787** | **0.7060** | **0.6461** | 0.6943 |
| EvoNeed Equal | 0.8465 | 0.6340 | 0.6181 | 0.6618 |
| EvoNeed Dynamic | 0.8447 | 0.6320 | 0.6142 | 0.6543 |
| EvoNeed Planned，每个 need 20 | 0.8388 | 0.6360 | 0.6092 | 0.6547 |

EvoLink 的主要价值仍然成立：相对同轮 Ours，Evidence Recall 提升 4.25 个百分点，Complete Recall 提升 9.60 个百分点；问题集中在前排排序，MRR 小幅下降 0.20 个百分点。因此不能说 EvoLink 整体失败，更准确的结论是“关联扩展有效补证，但关联强度不能直接代表问题相关性”。

EvoNeed 的原问题锚定让 Equal/Dynamic 的 Recall 比上一轮有所恢复，但仍未超过 EvoLink。Dynamic 仍略低于 Equal，说明当前 planner 给出的预算比例没有稳定转化成更好的有效候选，现阶段不宜把动态预算作为论文主贡献。

### 2.2 0.03 与 0.1 不能用两次绝对值直接比较

| 设置 | Ours Recall | EvoLink Recall | EvoLink 相对增量 | Ours MRR | EvoLink MRR | MRR 相对变化 |
|---|---:|---:|---:|---:|---:|---:|
| 权重 0.10 的旧轮次 | 0.8375 | 0.8728 | +0.0353 | 0.7017 | 0.6974 | -0.0043 |
| 权重 0.03 的新轮次 | 0.8362 | 0.8787 | +0.0425 | 0.6964 | 0.6943 | -0.0020 |

新轮次连未使用 EvoLink 的 Ours 都发生了变化，说明两轮并非完全相同的查询状态。当前 Query Planner 的缓存键包含运行日期，跨日会重新生成计划；因此绝对指标差异不能只归因于 0.03/0.1。

从同轮相对增量看，0.03 并没有明显更差。但它也没有形成足以支持重新定参的决定性证据。为避免继续在测试集上调参，并保持与既有主实验连续，后续恢复并固定 `EvoLink weight=0.1`。机制实验开始前应冻结 query plan 文件及其哈希，所有对照共用同一份计划。

## 三、9 月 4 日最佳 EvoNeed 到底怎么做的

结果目录：`data/exports/evaluation/2026-09-04_evoneed_planned_q100_r1`

它与现在的 Planned 不是同一种执行方式：

| 项目 | 9 月 4 日最佳版 | 当前纯 Query Planned |
|---|---|---|
| 查询集 | 原始数据前 100 题，其中只有 91 题有可评 Gold | 分层 Gold-500，500 题均有 Gold |
| Planner | EvoNeed v2 | EvoNeed v3 固定预算联合计划 |
| Need 数量 | 平均 2.73；允许多个 need 使用同一路径 | 平均 2.086；初始计划按路径去重 |
| 路径动作/100题 | vector 179、graph 31、event 63 | 每题每路最多一次 |
| 每个 need 的输出深度 | Top-20 | Top-20 |
| 内部候选深度 | multiplier=3，即每路先取最多 60 个底层候选 | multiplier=1 |
| EvoLink | 每个 need 分别扩展 | 全部 need 完成后只共享扩展一次 |
| 融合 | Need coverage fusion，最终 Top-20 | Need coverage fusion，最终 Top-20 |
| 在线 LLM | 规划、证据评估重排、回答，共 3 次 | 只规划 1 次 |

旧版平均每题从各动作返回 38.89 个去重候选，再融合为 Top-20。它的高召回来自更深的候选池、更多查询动作及多次 EvoLink，而不是仅仅来自“改写一次查询”。

证据评估模型没有改变 Top-20 的集合，因此 Recall 不变，但明显改善了排序：

| 指标 | LLM 评估重排前 | 重排后 | 增量 |
|---|---:|---:|---:|
| Evidence Recall@20 | 0.9130 | 0.9130 | 0 |
| Complete Recall@20 | 0.8132 | 0.8132 | 0 |
| nDCG@20 | 0.6893 | 0.7628 | +0.0735 |
| MRR@20 | 0.7034 | 0.8290 | +0.1256 |
| MAP@20 | 0.5819 | 0.6768 | +0.0949 |

这说明旧结果的两个来源很明确：

1. 候选覆盖来自高预算、多 need 查询和分别扩展；
2. 排名优势主要来自额外的 LLM 证据评估重排。

此外，旧 q100 与 Gold-500 只有 20 题重合，因此 0.9130 不能被当作 Gold-500 上可直接复现的结果。

## 四、如何合理复刻旧版

建议增加一个明确标注的高计算变体 `EvoNeed-Deep`，不替换固定预算的主实验：

1. 使用 v2 的证据需求 planner，允许最多三个 need，也允许两个 need 走同一路径；
2. 每个 need 返回 Top-20，底层 candidate multiplier=3；
3. 每个 need 独立执行 EvoLink，权重固定 0.1；
4. Need coverage fusion 得到 Top-20；
5. 调用一次相同的证据评估模型，只做 Top-20 重排；
6. 检索实验不必再调用答案模型，因为答案调用不会改变检索指标；端到端问答实验再统一接 reader。

这个版本每题包含一次规划和一次评估重排，共两次在线 LLM 调用。论文中应将它与纯 Query 版本分开报告，并增加两个匹配对照：

- `High-budget direct fusion`：相同底层候选深度，不做 need decomposition；
- `High-budget direct fusion + same LLM reranker`：相同候选深度和相同重排模型。

只有 `EvoNeed-Deep` 超过第二个对照，才能把收益归因到证据需求范式化，而不是“候选更多”或“多用了一个 LLM”。

## 五、下一阶段实验及目的

| 顺序 | 具体实验 | 要回答的问题 | 关键控制 |
|---|---|---|---|
| ① | 核查最新逐题结果和评测口径 | 当前提升是否在相同最终预算下成立？ | 区分文档包、chunk、底层候选和最终 Top-20；冻结 query plan |
| ② | 三路直接融合 vs 普通关联扩展 vs 完整 EvoLink | 跨视图回图扩展是否有独立收益？ | 相同索引、种子、候选深度、最终 Top-20 |
| ③ | 完整 EvoLink vs 关闭事件—断言作用边 | 事实演化连接是否比一般实体—事件参与关系更有用？ | 保留实体、事件及 ACTOR/OBJECT 等参与边，只关闭作用边 |
| ④ | 新增 Gold 与噪声诊断 | EvoLink 补回了什么证据，代价是什么？ | 记录新增/丢失 Gold、扩展路径、最终名次、问题类型和新增非 Gold |
| ⑤ | 小规模筛查 EnterpriseRAG-Bench | 机制能否迁移到办公多文档变更追溯？ | 先固定筛选规则，再筛项目综合、冲突、完整性及状态变更题 |
| ⑥ | 统一 Reader 的回答实验 | 更多、更完整的证据是否改善最终答案？ | 同模型、prompt、温度、原文 token 上限和一次回答调用 |

其中②③④是论文机制论证的核心。HippoRAG、EventRAG、E²RAG 等保留为外部方法比较；另增加候选预算充分的 Hybrid 对照，防止把“多取候选”误写成图机制收益。任何改变预算或功能的基线必须在名称和表注中明确说明。

## 六、演化断言消融怎样做才有效

不能只删事件类型或时间标签，因为当前检索排序并不充分依赖这些标签。应直接控制图中实际参与扩展的连接：

1. `Direct Fusion`：不做回图扩展；
2. `Association-only EvoLink`：允许实体—事件参与边及普通实体关系连接，但禁用事件→断言的作用边；
3. `Full EvoLink`：在上一步基础上启用 `CREATES / UPDATES / TERMINATES / SUPERSEDES / DENIES / CONFIRMS` 作用边及其有效时间。

若 Full 显著超过 Association-only，才能证明“事件对事实状态的作用表示”具有独立检索价值；若二者接近，则演化表示应降为支撑设计，主创新收敛到跨视图协同扩展。

## 七、创新点收敛

总体定位：

> 面向跨文档事实演化的实体—事件协同证据检索。

核心问题：

> 同一对象的事实及其变更依据分散在不同材料中，如何在有限检索预算内找齐回答所需的关联证据？

候选创新点：

### 1. 事件作用驱动的事实演化表示

将事实断言独立表示，用创建、确认、更新、否认、终止和替代等作用关系连接事件与断言，并保留有效时间及原文来源。需要通过 Full EvoLink 与 Association-only 的差异证明这些作用连接能补回普通实体关系和时间标签难以发现的 Gold Evidence。

### 2. 实体—事件双视图协同的证据扩展

从实体关系视图与事件视图获取互补种子，回到共享证据图进行一次受限扩展，再融合为可追溯的原文证据。需要通过 Direct Fusion、Association-only 和 Full EvoLink 的阶梯对照证明其提高证据完整召回，而不只是增加候选数量。

最终按结果收敛：

- 两级机制均有独立收益：主打“跨文档事实演化的证据检索”；
- 只有跨视图扩展有效：主打“实体—事件协同的多文档证据检索”，演化表示作为支撑；
- 办公数据迁移不足：保留跨文档检索定位，办公变更追溯只作为应用动机。

## 八、立即执行顺序

1. 固定 EvoLink 权重 0.1，冻结 Gold-500、query plan 和所有索引；
2. 先实现并运行 Direct / Association-only / Full 三档机制对照；
3. 生成逐题新增 Gold、丢失 Gold、扩展路径和噪声分析；
4. 并行准备 `EvoNeed-Deep` 的独立高计算复刻，但不混入固定预算主表；
5. 机制结论稳定后，再开展办公数据筛查和统一 Reader 实验。

当前最优先的是②③④，而不是继续调 EvoNeed 的预算数字。
